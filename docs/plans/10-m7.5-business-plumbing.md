### 3.3 Lisensi produk: signed file, offline, jujur (threat model "honest customer")

**Threat model eksplisit:** yang kita lindungi adalah **pelanggan jujur** — mencegah pemakaian melebihi edisi *secara tidak sengaja*, memberi dasar percakapan sales ("kamu pakai 40 device di lisensi 10 seat"), dan membuat batas edisi terlihat jelas di produk. Kita **tidak** mencoba menghentikan orang yang mau patch binary atau tukar public key — itu selalu mungkin pada software self-hosted, dan usaha DRM hanya menyakiti pelanggan jujur (offline install, CI, air-gapped). Konsekuensi desain:

- License = **file JSON bertanda tangan Ed25519**, verifikasi offline dengan public key yang tertanam di core. Tidak ada network call.
- Tanpa lisensi / lisensi invalid / expired → **fallback ke edisi `community`** yang tetap berfungsi (bukan brick), dengan banner informatif di Studio.
- Batas edisi = **konfigurasi terpusat** (`editions.ts`) + satu modul enforcement. Kode fitur bertanya `licenseService.can('x')` / `licenseService.limit('maxDevices')` — tidak pernah baca file lisensi sendiri.

### 3.4 Telemetry: opt-in sungguhan (spec §18)

Default OFF; tidak ada "opt-out tersembunyi". Consent diminta sekali di first-run wizard (setelah AUP) dan bisa diubah kapan pun di Settings. Event minimal dan bisa diaudit user (tombol "preview payload" menampilkan persis JSON yang akan dikirim). `installId` = UUID acak yang bisa di-reset user; tidak ada serial device, email, nama, IP yang sengaja disimpan.

### 3.5 AUP: bagian produk, bukan cuma dokumen (spec §17, §9.4)

AUP menegaskan positioning QA/test-automation dan mengikat ke perilaku produk nyata: fitur instrumentation/tagging trafik farm **on by default** (spec §9.4) disebut di AUP sebagai bagian desain — bukan janji kosong. AUP di-acknowledge saat setup admin pertama (checkbox + tombol, dicatat di `audit_log` dengan versi AUP), dan tersedia permanen via `GET /api/legal/aup` + halaman Studio.

### 3.6 Update channel: pull sederhana

Core/Studio cek file **release feed JSON statis** (di-host di GitHub Releases / GitHub Pages — URL final Open question) → bandingkan semver. Tidak ada auto-download di mode server/Docker (admin update manual sesuai install guide); auto-update binary desktop sudah urusan Tauri (Plan 09) — halaman ini hanya *memberi tahu*.

### 4.2 License file & verifikasi (Ed25519)

Format file `enkaku-license.json` (ditaruh di app-data dir sebagai `license.json`, atau path override `ENKAKU_LICENSE_FILE`, atau upload via Studio → disimpan core ke app-data):

```ts
// packages/core/src/license/license-file.ts
import { z } from 'zod'
import { createPublicKey, verify as edVerify } from 'node:crypto'

export const LicensePayload = z.object({
  v: z.literal(1),                        // versi format lisensi
  licenseId: z.string().min(8),
  edition: z.enum(['pro', 'enterprise']), // community tidak butuh file
  seats: z.number().int().positive(),     // jumlah user
  maxDevices: z.number().int().positive().nullable(), // null = unlimited
  issuedTo: z.string().min(1),            // nama customer (tampil di UI)
  issuedAt: z.number().int(),             // unix epoch detik
  expiresAt: z.number().int().nullable(), // null = perpetual
})
export type LicensePayload = z.infer<typeof LicensePayload>

export const LicenseFile = z.object({
  payload: LicensePayload,
  signature: z.string(),                  // base64(Ed25519 sign(canonicalJson(payload)))
})

// Kanonikalisasi: JSON.stringify dengan key tersortir rekursif — sign & verify
// HARUS memakai fungsi yang sama persis (satu-satunya sumber: file ini,
// diimport juga oleh scripts/license-tool.ts).
export function canonicalJson(value: unknown): string { /* sort keys rekursif */ }

// Public key SPKI (base64) di-embed sebagai konstanta. Private key TIDAK PERNAH
// masuk repo — dipegang maintainer offline (lihat docs/dev/release-process.md).
export const ENKAKU_LICENSE_PUBKEY_SPKI_B64 = '<diisi saat keygen pertama>'

export type LicenseVerifyResult =
  | { status: 'valid'; payload: LicensePayload }
  | { status: 'expired'; payload: LicensePayload }
  | { status: 'invalid'; reason: 'bad-json' | 'bad-schema' | 'bad-signature' }

export function verifyLicenseFile(raw: string, now = Date.now() / 1000): LicenseVerifyResult {
  let parsed: unknown
  try { parsed = JSON.parse(raw) } catch { return { status: 'invalid', reason: 'bad-json' } }
  const file = LicenseFile.safeParse(parsed)
  if (!file.success) return { status: 'invalid', reason: 'bad-schema' }

  const key = createPublicKey({
    key: Buffer.from(ENKAKU_LICENSE_PUBKEY_SPKI_B64, 'base64'),
    format: 'der', type: 'spki',
  })
  const ok = edVerify(null,
    Buffer.from(canonicalJson(file.data.payload)),
    key,
    Buffer.from(file.data.signature, 'base64'))
  if (!ok) return { status: 'invalid', reason: 'bad-signature' }

  const { expiresAt } = file.data.payload
  if (expiresAt !== null && now > expiresAt) return { status: 'expired', payload: file.data.payload }
  return { status: 'valid', payload: file.data.payload }
}
```

export type Edition = 'community' | 'pro' | 'enterprise'

export const EDITIONS: Record<Edition, EditionLimits> = {
  community:  { maxDevices: 3,    maxUsers: 1,    features: { multiUser: false, cloudTunnel: false, telemetryRequired: false } },
  pro:        { maxDevices: null, maxUsers: null, features: { multiUser: true,  cloudTunnel: false, telemetryRequired: false } },
  enterprise: { maxDevices: null, maxUsers: null, features: { multiUser: true,  cloudTunnel: true,  telemetryRequired: false } },

`license-service.ts` (dipakai seluruh core):

```ts
export interface LicenseState {
  edition: Edition
  limits: EditionLimits                // hasil merge EDITIONS[edition] ∩ payload lisensi
  status: 'none' | 'valid' | 'expired' | 'invalid'
  payload?: LicensePayload             // hanya bila ada file (valid/expired)
}

export interface LicenseService {
  state(): LicenseState
  can(feature: keyof EditionLimits['features']): boolean
  assertWithinLimit(kind: 'devices' | 'users', currentCount: number): void // throw EnkakuError('EDITION_LIMIT')
  reload(): Promise<LicenseState>      // dipanggil setelah upload/hapus license
}
```

Titik enforcement (semua lewat `assertWithinLimit`/`can`, tidak ada pengecekan lain):
1. **Device enrollment** (handler enroll Plan 03): sebelum insert device baru → `assertWithinLimit('devices', count)`. Device yang sudah terlanjur terdaftar saat downgrade **tidak dihapus** — hanya enrollment baru yang ditolak + banner.
2. **User create** (Plan 09): `assertWithinLimit('users', count)`.
3. **Feature gate** `multiUser`: form tambah user disable di community (server tetap validasi).

### 4.8 Versioning & kompatibilitas protocol

- **Core**: semver. Breaking pada perilaku API/WS atau format app-data → major. Fitur → minor. Fix → patch.
- **`@enkaku/protocol`**: versinya independen tapi core mendeklarasikan `protocolVersion` yang dia bicarakan; Studio (bila di-serve terpisah/hosted) menolak konek + pesan jelas kalau major protocol beda. Penambahan message type/field opsional = minor (kompatibel); mengubah/menghapus field = major.
- **`@enkaku/sdk`**: semver sendiri; bundle script menyimpan `sdkVersion` (sudah dari Plan 05) — core menolak bundle dari sdk major yang lebih baru dari yang dia dukung.
- **Toolchain coupling**: naik versi scrcpy-server = rilis core (spec §7.6) → update `compatibleCoreRange` di manifest = item wajib checklist rilis.

Release checklist (isi `release-process.md`, ~urutan):
1. `CHANGELOG.md` diupdate (Keep a Changelog; bagian Unreleased → versi).
2. Bump versi core (+ protocol/sdk bila berubah) — satu commit `chore(release): vX.Y.Z`.
3. `bun test` hijau seluruh workspace; smoke test single-binary di macOS + Linux.
4. Build matrix: macOS arm64/x64, Linux x64/arm64 (binary), Docker image multi-arch, Tauri bundle.
5. Regenerate `LICENSES.md` bagian npm (`bun scripts/scan-licenses.ts`) — diff harus direview.
6. Update manifest toolchain bila ada perubahan versi tool (checksum + `compatibleCoreRange`).
7. Tag git `vX.Y.Z`, buat GitHub Release + upload artifact + checksum.
8. Update `release/feed.json` (versi, notesUrl, downloads) dan publish ke URL feed.
9. Verifikasi: instalasi lama klik "Check for updates" → melihat rilis baru.

## 7. Test plan

### Unit test (`bun test`)

`license-file.test.ts` (pakai keypair test digenerate di test, pubkey di-inject):
- sign → verify → `valid`, payload utuh.
- `expiresAt` lampau → `expired` (payload tetap terbaca).
- `expiresAt: null` → `valid` (perpetual).
- Payload diubah 1 field setelah sign (tampered) → `invalid/bad-signature`.
- Signature diganti acak → `invalid/bad-signature`; JSON rusak → `bad-json`; field kurang → `bad-schema`.
- `canonicalJson` stabil terhadap urutan key input.

`editions.test.ts` + `license-service`:
- Tanpa file → community; merge: license `maxDevices: 20` < edition unlimited → limit efektif 20.
- `assertWithinLimit('devices', N)` throw `EDITION_LIMIT` tepat di batas; tidak throw di bawah batas.
- Downgrade (hapus lisensi) tidak menghapus device — hanya enrollment baru ditolak.

`telemetry-service.test.ts`:
- Default OFF; `record()` saat OFF → buffer kosong & fetch mock **tidak pernah** terpanggil.
- ON → flush → payload lolos `TelemetryEnvelope.parse`; event crash hanya berisi `errorCode`/`subsystem` (assert tidak ada key lain).
- Endpoint gagal (fetch reject) → tidak throw, tidak retry-loop.

`release-feed.test.ts`:
- Parse feed fixture valid; feed korup → error terkontrol.
- `compareSemver`: lebih baru / sama / lebih lama / prerelease.

## 8. Risiko & mitigasi

| Risiko | Dampak | Mitigasi |
|---|---|---|
| Interpretasi ToS Google (platform-tools) keliru | Legal saat jual | Kebijakan paling konservatif (tidak redistribute, download resmi) + tandai `NEEDS HUMAN LEGAL REVIEW` + prosedur audit terdokumentasi dengan URL & tanggal sumber. |
| Private key lisensi bocor / hilang | Bocor: lisensi palsu beredar; hilang: tak bisa terbit lisensi baru | Key offline, tidak di repo/CI; prosedur penyimpanan + rencana rotasi (format lisensi `v` memungkinkan pubkey baru di rilis core berikutnya) di release-process.md. |
| Edition limits merembes ke banyak file seiring waktu | Sulit diubah, bug inkonsisten | Aturan tunggal `editions.ts` + acceptance criterion grep + review checklist rilis. |
| Telemetry merusak kepercayaan (kesan diam-diam) | Reputasi produk self-host | Default OFF keras, preview payload, privacy.md digenerate-konsisten dengan schema, crash tanpa message/stack. |
| Docs cepat basi terhadap perilaku nyata | Onboarding gagal = churn | Contoh kode di-type-check via test; link-check di CI; checklist rilis memuat "review docs berubah?". |
| `bunx license-checker` tidak akurat/tidak jalan di Bun | Audit npm bolong | Script wrapper punya fallback parse manual; hasil selalu direview manusia sebelum rilis (checklist). |
| Update check dianggap phone-home | Kepercayaan | Hanya on-demand (klik tombol), tidak ada payload selain HTTP GET feed statis; didokumentasikan di privacy.md. |

## 9. Open questions

Butuh keputusan manusia — jangan diputuskan sepihak oleh agent builder:

1. **Legal review** (blocking sebelum jual, tidak blocking merge plan): (a) interpretasi final ToS Google platform-tools — apakah kebijakan "download resmi + mirror sendiri untuk air-gapped" cukup; (b) lisensi ui-server bila ada kode derivatif openatx; (c) redroid sebelum M8; (d) review AUP oleh counsel.
2. **Angka & isi edisi**: community 3 device / 1 user hanyalah placeholder — berapa angka final? Apakah perlu edisi `pro` vs `enterprise` atau cukup dua tier? Harga bukan scope plan ini.
3. **Phone-home / server aktivasi online**: fase ini offline-only. Perlu kah nanti (revocation, seat tracking)? Kalau ya → proyek terpisah.
4. **Kebijakan expiry**: sekarang expired → langsung fallback community (tanpa grace). Alternatif: grace period, atau model "perpetual fallback" (versi yang dirilis sebelum expiry tetap berfungsi selamanya). Pilihan bisnis.
5. **Telemetry ingest**: self-host endpoint kecil vs layanan pihak ketiga (PostHog/Plausible-style)? Mempengaruhi privacy.md (retensi, subprocessor) dan `ENKAKU_TELEMETRY_URL`.
6. **Docs tooling**: kapan pindah dari markdown polos ke site generator (Docusaurus/VitePress/Starlight), dan di-host di mana?
7. **Bahasa docs user**: English-only atau English + Indonesia?
8. **URL kanonik**: domain release feed, email support, lokasi hosting feed (GitHub Pages vs domain sendiri) — nilai final untuk `support.ts` dan konstanta feed.
9. **Nama produk**: "Enkaku" masih codename (spec header) — AUP/LICENSES/docs memakai nama ini; ganti nama = find-replace terkontrol sebelum rilis publik.
